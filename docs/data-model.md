# 赶海雷达数据模型

当前前端使用 `utils/data.js` 的演示数据，接入云开发后建议拆成以下集合：

## spots

赶海点基础资料：名称、区域、经纬度、入口、停车、卫生间、风险等级、潮汐站。

## zones

地点内部微区域：GeoJSON 多边形、东/西/中侧、底质、推荐品类、离岸距离带、风向暴露、最晚撤离提前量。

## forecasts

按日期和地点缓存天气、潮汐、风浪、赶海指数、品类概率、预测可信度。

## catch_reports

用户上报：地点、区域、时间、品类、收获等级、照片、备注、审核状态。精确定位只用于校准，不对外展示用户个人轨迹。

## provider_snapshots

保存每次天气、潮汐接口返回的原始快照和更新时间，方便排错、回溯与模型评估。

## 预测原则

1. 先做安全闸门，再算海货评分。
2. 数据不足时输出低可信度，不制造精确产量。
3. AI只解释结构化结果，不直接生成潮汐或地点事实。
4. 现场封闭、海洋预警、强风浪时，推荐直接降级为“不建议下海”。
5. 品类预测必须同时记录“发现”和“未发现”，不用只有战果的数据直接估计概率。
6. 海肠专项是相对冲岸指数，使用底质先验、近18小时风浪和洋流向岸分量、潮汐窗口与近90天正负样本；样本不足时必须显示低置信。
