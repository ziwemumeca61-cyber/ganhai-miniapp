# 全国赶海雷达微信小程序

面向全国沿海城市的赶海辅助小程序，当前包含：

- 自动定位最近沿海城市，也可手动切换城市
- 仅对当前城市地点进行距离与安全综合排序
- 全国沿海赶海点、地图、潮汐、天气与安全评分
- 地点方位、退潮参考范围、目标海货和撤离提醒
- 跟随当前城市数据的规则筛选助手
- 赶海圈使用微信官方贴图组件处理公开图文
- 公开分享交给官方组件，仅匿名结构化现场样本参与预测
- 按参考点西侧、附近、东侧积累岸段样本，逐步校准最佳赶海区域
- 地点位置、入口和采集规定纠错反馈
- 地点详情明确展示优先赶海岸段、到达路线和现场识别特征
- 实时接口异常时使用10分钟内最近有效海况缓存
- 首页先展示本地地点，海况、定位和现场样本分别更新；同城请求复用，缓存标明时间
- 烟台候选岸段海肠冲岸指数（近18小时风向、浪向、浪周期、洋流、岸线和正负现场样本）

## 打开方式

1. 使用微信开发者工具导入本目录。
2. 使用项目的正式小程序 AppID，并确认 `app.js` 中云环境 ID 正确。
3. 在小程序后台申请 `wx.getLocation`，并保持 `app.json` 中的位置用途声明。

## 云端部署

需要分别右键上传并部署：

- `cloudfunctions/forecast`：天气、海况和潮汐
- `cloudfunctions/report`：匿名现场样本、定位验真和样本汇总

本轮海况修复需要重新部署 `forecast`，并在云开发控制台将它的执行超时设为 **20 秒**。只更新前端不会更新云函数。新版返回版本号 `forecast-20261019.1`；首页“查看原因”或底部数据说明中可核对云端版本与具体错误。

海况两分钟内复用；超过十分钟或跨北京时间日期的缓存停止评分。下拉刷新或“重试”会绕过新鲜缓存。现场样本查询不阻塞海况；提交样本后会清理样本缓存。缓存只包含公开城市海况，不保存用户精确位置。

回归验证：`node scripts/test-startup.js`，覆盖首帧展示、慢请求、请求合并、缓存过期与跨日、城市切换、定位进度、官方预报新旧地名和浪高变化解析。

需要创建以下云数据库集合：

- `field_reports`：现场收获记录
- `spot_feedback`：地点纠错反馈
- `forecast_cache`：最近一次有效海况缓存

赶海圈公开图文由微信官方组件处理，小程序不存储或分发。结构化现场样本需通过定位核验；精确经纬度只参与当次距离计算，不写入数据库。请同时鼓励用户提交“未发现”记录，否则品类模型会出现幸存者偏差。每次调整 `utils/data.js` 中的地点后，运行 `node scripts/sync-report-spots.js`，确保云函数白名单与前端地点同步。
